# Task spec for the coding workers

Implement the two stub modules in `src/todoapp/`. Each worker owns exactly one
file and its matching test file. Do not edit the other worker's files, do not
edit `run.py`, and do not edit this file.

## Module 1 — `src/todoapp/storage.py` (worker 1)

The data layer. No HTTP here; `storage.py` must not import anything from
`server.py`.

```python
class TodoStore:
    def __init__(self) -> None: ...
    def add(self, title: str) -> dict: ...
    def get(self, todo_id: int) -> dict | None: ...
    def list_all(self) -> list[dict]: ...
    def complete(self, todo_id: int) -> dict | None: ...
    def delete(self, todo_id: int) -> bool: ...
```

A todo is a dict with exactly these keys: `id` (int), `title` (str),
`done` (bool, starts `False`).

Rules:

- `add("")` or `add("   ")` raises `ValueError`. An empty title is not a todo.
- `add` returns the new todo, including its assigned `id`.
- Ids start at 1 and increment by 1 per todo. Never reuse an id, including after
  a `delete`.
- `get` returns `None` for an unknown id, never raises.
- `complete` on an unknown id returns `None`. On a known id it sets `done` to
  `True` and returns the todo. Completing an already-complete todo is not an
  error and returns the todo unchanged.
- `delete` returns `True` if something was removed, `False` if the id was
  unknown.
- `list_all` returns todos in ascending id order. It returns `[]` when empty,
  not `None`.
- `list_all` must not hand out the internal dicts. A caller mutating what it
  got back must not change the store. Return copies.

## Module 2 — `src/todoapp/server.py` (worker 2)

HTTP on top of the store. Import `TodoStore` from `storage`; do not reimplement
storage here.

```python
class TodoServer:
    def __init__(self, store: TodoStore, host: str = "127.0.0.1",
                 port: int = 8765) -> None: ...
    def handle(self, method: str, path: str, body: bytes | None = None) -> tuple[int, dict]: ...
    def start(self) -> None: ...
```

`handle` is the whole HTTP contract and is directly unit-testable without
binding a socket. `start` serves it.

### Routes

| Method | Path | Success | Body |
| --- | --- | --- | --- |
| GET | `/todos` | 200 | `{"todos": [...]}` |
| POST | `/todos` | 201 | the created todo |
| GET | `/todos/<id>` | 200 | the todo |
| DELETE | `/todos/<id>` | 204 | empty |
| GET | `/health` | 200 | `{"status": "ok"}` |

### Rules

- JSON in, JSON out. Content type `application/json`.
- POST `/todos` reads `{"title": "..."}`. Missing `title`, or a non-string
  `title`, returns **400** with `{"error": "..."}`. Never a 500.
- An empty or whitespace-only title returns **400**. Same body shape.
- Unknown id on GET or DELETE returns **404** with `{"error": "..."}`.
- POST `/todos/<id>` or any other unlisted method/path returns **405** when the
  path shape is known, and **404** when the path is unknown. Do not return 400
  for a wrong method.
- `/todos/abc` (non-numeric id) returns **404**, not 400.
- A 204 response has an empty body, not `{}`.
- A malformed JSON request body returns **400**, not a traceback.
- `GET /health` never touches the store and always returns 200. It is what the
  pipeline waits for to know the server is up.

## Definition of done

- Every test in the matching `tests/` file passes.
- `python3 -m unittest discover -s tests -v` passes from `workspace/demo-project`.
- `python3 run.py` starts, and `curl 127.0.0.1:8765/health` returns
  `{"status": "ok"}`. Check this yourself rather than assuming.
- Both modules import cleanly; `storage.py` does not import `server.py`.
- No module imports a third-party package. `pytest`, `flask` and `requests` are
  not installed.
