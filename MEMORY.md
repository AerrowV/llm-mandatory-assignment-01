## CONFIGURATION RESTRUCTURE (2026-10-04, after the section below)

`scripts/agent.py` is no longer the only place that knows anything. Two hardcoded
things caused all of the friction above, and both are gone:

**1. Model choice lived in four files.** Now it lives in **one file: root `.env`**.
`endpoints/.env` is deleted. `scripts/config.py` parses `.env` and generates
`endpoints/config.yml` plus all 14 profile JSONs (7 LLM + 7 agent). Every one of
them carries a `_comment` saying "generated by scripts/config.py - edit .env, not
this file." They stay committed so a fresh clone works before anything runs, and
`python3 scripts/config.py --check` fails if they have drifted from `.env`.
`scripts/agent.py` regenerates them on every `start`, and `docker/validate.sh`
fails on drift too. Changing `ENDPOINT_B_MODEL` in `.env` is now the *only* edit
needed to move every execution role onto another model.

**2. Prompts were split between `openhands/prompts/` and inline strings in
`scripts/pipeline.py`.** All role prompts now live in **root `prompts/`** —
`01-architect`, `02-tech-lead`, `03-implementation`, `04-testing`,
`05-documentation`, `06-deployment`, plus `00-demo.md` (was `DEFAULT_TASK` in
`demo.py`) and `fragments/worktree-scope.md`. The two briefs that were inline in
`pipeline.py` are now `05-documentation.md` and `06-deployment.md`. Nothing in
`scripts/` contains prompt text any more, so a role's wording can be changed
without touching a line of Python.

Paths in this file that predate the move read `openhands/prompts/NN-*.md`; the
same file is now `prompts/NN-*.md`. The replay harness command below needs that
one substitution.

The coder stage had been failing for hours with **zero tool calls**. Root cause is

300 s timeout with the weights resident (9787 MB per `/api/ps`) and **zero tokens
billed**. It stayed wedged after `keep_alive:0` *and* after restarting the ollama
process on port 11435, so it was the model, not the server.

in `endpoints/config.yml` as the documented fallback and passes
`endpoints/toolcheck.py` (direct *and* via proxy). Note the trap: `toolcheck.py`

After the swap the model was clearly being called (33 k prompt tokens) but every
assistant turn came back as `content: ''`, so OpenHands retried three times with

  `content: ''`, `tool_calls: null`. So the model emits ~39 tokens that Ollama

- The **identical payload works on endpoint A's `qwen2.5:3b`** (valid `think` call,
  84 tokens). Only the 7b model on endpoint B fails.

## HARD-WON FAILURE MODES (all silent unless stated)

1. **A model can stop answering while every health endpoint stays green.**
   `/v1/models` answers, the proxy logs `200 OK`, and the agent sits at
   `execution_status: running` with 0 tokens. Probe the port with a bare
   completion before blaming a prompt.
2. **Ollama drops an unparseable tool call and returns an empty message** with
   `finish_reason: stop` and ~39 completion tokens. LiteLLM forwards it, OpenHands
   reports "did not include a function call or a message". A long task prompt can
   push `qwen2.5:7b-instruct` into this. Not reproducible with `toolcheck.py`.
3. **A passing `toolcheck.py` does not prove the agent loop works.** It uses one
   small prompt; the agent sends ~11 k tokens with 20 real tool schemas.
4. **Skills are injected regardless of settings flags.** `enabled_skills: []` in
   `openhands/state/settings.json` was not enough. What worked was an 86-name
   `disabled_skills` deny-list on all seven `openhands/state/agent-profiles/*.json`.
5. **`git worktree add` without `--relative-paths`** produces a `.git` pointer that
   is invalid inside `/opt/project`.
6. **Workers are told not to run git**, so output must be committed by the harness
   (`commit_worktree()`) before `drop_worktree()` merges, or the merge sees an empty
   diff.
7. **`llama3.1:8b` names a second tool in the prompt, it stops calling tools at
   all.** With the real agent request (full system prompt + all 20 schemas), a
   prompt that names **exactly one** tool produced a real `tool_calls` 10/10
   times; naming **two** tools produced prose ("Here is the JSON for the function
   call with its proper arguments") almost every time. Controlled pair, identical
   content, matched length: one tool 2/2 tool calls, two tools 2/2 prose.
   - Length is **not** the cause: a 2980-char single-tool prompt padded with
     neutral prose worked, while a 2948-char two-tool prompt failed. Nor is it the
     numbered step list, nor the backticked shell command: single-tool versions of
     both worked.
   - Reproduce offline in ~1 min instead of burning 4-minute agent runs:
     `sim_tester.py` feeds the captured real system prompt + 20 schemas and
     reports tool_calls-vs-prose. `/var/.../opencode/sim_tester.py`.
   - Consequence: `prompts/04-testing.md` (tester) and `05-documentation.md` both
     need `terminal` + `file_editor`, so both hit this. `03-implementation.md`
     names only `file_editor`, which is why the coders work.
